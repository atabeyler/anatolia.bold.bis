# Repository Agent Instructions

These instructions apply to all automated development agents working in this repository.

## Workflow
- All work targets the original `main` branch — every branch, commit, and pull request exists to move `main` forward, not to establish a separate line of history.
- Keep commits focused, atomic, and descriptive.
- Never modify global Git configuration. Use repository-local identity only:
  - `git config --local user.name "atabeyler"`
  - `git config --local user.email "info@boldkimya.com.tr"`
- **Always ask the repository owner for confirmation before running `git push`** (to any branch), regardless of how small or routine the change looks. Commits may be prepared locally, but the push itself is never automatic.

## Commit and Pull Request Style
- Use professional, human-written commit messages.
- Use professional pull request titles and descriptions.
- Do not include statements, signatures, trailers, emojis, badges, footers, session IDs, or any wording that indicates AI or automated assistance — in commit messages, PR titles/descriptions, PR comments, merge messages, branch names, code comments, or changelog entries.
- Do not mention AI tools, language models, assistants, or generated content anywhere in the repository's history or documentation.
- Never add "Co-Authored-By" trailers for automated tools, "Generated by ..." notes, or tool names in branch names.
- Commits and pull requests must read as normal, professional engineering work.

## Code Standards
- All source code, file names, identifiers (variables, functions, classes), comments, logs, tests, and documentation must be written in English — with no exceptions.
- All user-facing text must use the internationalization (i18n) system from the very first implementation, and in every subsequent change — no hardcoded user-facing strings are ever introduced, including during prototyping.
- Supported languages (6 total): English (default/fallback), Turkish, German, French, Arabic, Russian.
- Arabic must render with full RTL layout; all other languages use LTR.
- Every locale file must carry the same set of translation keys — no partial or placeholder translations.
