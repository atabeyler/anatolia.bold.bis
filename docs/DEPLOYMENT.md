# Deployment

## Target: Render

The backend deploys to Render as a native Rust binary — there is no Node
process at runtime for the API itself (the frontend build only runs during
the Render build step, if the frontend is deployed alongside it).

- **Build**: `cargo build --release` inside `server/`.
- **Start**: the resulting `anatolia-bis-server` binary.
- **Health check**: `GET /api/health`. Its `version` field is the exact
  commit SHA of the running build (embedded at compile time by
  `server/build.rs`) — compare it against a pushed commit to confirm a
  deployment actually went live, rather than assuming from push time
  alone.

`render.yaml` at the repository root is a Render Blueprint defining all
three resources:
- `anatolia-bis-db` — managed PostgreSQL.
- `anatolia-bis-api` — the backend above (native Rust, `rootDir: server`).
- `anatolia-bis-web` — the frontend as a static site (`rootDir: client`,
  `npm install && npm run build`, published from `dist`), with an SPA
  rewrite so client-side routes resolve on a hard refresh.

To provision: Render dashboard → **New +** → **Blueprint** → select this
repository. Render reads `render.yaml` and creates all three resources
together. A handful of secrets are intentionally left for the dashboard
(`sync: false` in the blueprint) rather than committed: `ADMIN_USER_CODE`,
`ADMIN_PASSWORD`, `ADMIN_EMAIL`, `ALLOWED_ORIGINS`, `APP_URL`,
`RESEND_API_KEY` (backend), and `VITE_API_BASE_URL` (frontend, set once
the backend's own Render URL is known). `JWT_SECRET`, `JWT_REFRESH_SECRET`,
and `ADMIN_SEED_TOKEN` are auto-generated by Render (`generateValue: true`)
— rotate them there if ever needed, not by editing the blueprint.
After the first deploy, seed the admin account per `API.md`'s
`POST /api/v1/admin/seed-admin`, using the auto-generated
`ADMIN_SEED_TOKEN` from the Render dashboard.

## Local: Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

Starts three services: `postgres` (PostgreSQL 16), `api` (the Rust
backend), and `web` (the frontend, built and served via nginx). Note: the
Phase 1 backend does not yet read `DATABASE_URL` or connect to Postgres —
that wiring lands in Phase 2.
